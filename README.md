## Product direction

Explore a distinctive browsing experience with an original Shallette interface and visual identity. The project model is still open: Shallette may become a clean-room implementation, a fork, or a downstream build. That decision will shape the architecture, license review, and release process.

### Design principles

- **Recognizably Shallette:** create original interface details, visual assets, and product language.
- **Clear provenance:** make the source, upstream revisions, changes, and build inputs traceable.
- **Independent presentation:** describe any technical relationship to other projects accurately and avoid implying endorsement.
- **Evidence-led releases:** document supported systems and release artifacts only after they have been built and verified.

## Roadmap

The project is currently in **Phase 0: foundation**. The next phases are planning targets, not delivery commitments.

1. **Set the foundation** — choose the project model, confirm the intended repository visibility, and complete an initial source, license, and trademark review.
2. **Define the product** — approve the product brief, design principles, original identity, and the first supported platform targets.
3. **Specify the architecture** — document the browser engine relationship, component boundaries, update approach, and upstream maintenance strategy.
4. **Build and evaluate a prototype** — add implementation, reproducible development instructions, and platform-specific validation once the architecture is approved.
5. **Prepare a release** — complete security reporting, attribution, license notices, signing, artifact provenance, and release documentation before distributing binaries.

See [`docs/ROADMAP.md`](docs/ROADMAP.md) for phase goals and completion criteria.
