# Platforms — badge edition per OS

Badge edition 0.0.1 artifacts (from upstream Zen 1.23.4b packages, same rebrand
procedure per platform). Source of truth for the procedure: `docs/BADGE-EDITION.md`
(Linux section) — the other platforms reuse it with the layout notes below.

| Artifact | Status | Size |
| --- | --- | --- |
| `shallette-0.0.1-linux-x86_64.tar.xz` | **tested on the dev host** (see TESTING.md) | 175 MB |
| `shallette-0.0.1-windows-x86_64-portable.zip` | assembled, **not executed on Windows yet** | 248 MB |
| `shallette-0.0.1-macos-universal.app.zip` | assembled, **not executed on macOS yet** | 247 MB |

## Windows (portable zip, not the installer)

Source: upstream `zen.installer.exe` (NSIS-ish, readable by 7z). The installer is NOT
repacked — instead the extracted `core/` becomes a portable folder:

- `core/browser/omni.ja`: unpacked, same string sweep (brand.ftl × locales, `\bZen\b`,
  update/telemetry prefs, branding assets with rune+portrait), repacked with python
  `zipfile` (deflate, no zip64).
- `core/application.ini`: Name=Shallette, Vendor=Shallette Project, Version=0.0.1.
- `core/browser/VisualElements/VisualElements_{70,150}.png`: portrait renders
  (Start tiles); the `*VisualElementsManifest.xml` reference them as before.
- `zen.exe` renamed to `shallette.exe`; `shallette.cmd` sets
  `MOZ_APP_REMOTINGNAME=shallette` and runs with a portable `-profile` next to the exe.

Known limits: the taskbar icon comes from the exe's embedded resource (still upstream's
until a source build); the NSIS installer is not repackaged — portable zip only.

## macOS (app bundle zip, not a dmg)

Source: upstream `zen.macos-universal.dmg` (HFS, readable by 7z). Rebrand applied to
`Shallette.app` (renamed from `Zen.app`):

- `Contents/Resources/browser/omni.ja`: same rebrand; the root `Contents/MacOS/omni.ja`
  is brand-clean upstream and stays untouched (verified on Linux, same layout).
- `Contents/Resources/application.ini`: Name/Vendor/Version as above.
- `Contents/Info.plist`: CFBundleName=Shallette, CFBundleExecutable=shallette
  (binary renamed), CFBundleIconFile=shallette.icns, CFBundleIdentifier=app.shallette.desktop.
- `shallette.icns` generated by hand (icns container with PNG chunks icp4…ic14 from the
  portrait renders); upstream `firefox.icns` removed — another upstream leftover name.
- All `_CodeSignature` directories and `embedded.provisionprofile` removed: the bundle is
  **unsigned**. On macOS: `xattr -cr Shallette.app`, then right-click → Open.
- Executables re-marked 755 (7z extraction loses the exec bit).

Known limits: repacked on Linux — the bundle is not notarized/signed; a native `hdiutil`
pass is recommended before any distribution. Updater helpers keep upstream identity
strings (they are not user-facing).

## What "tested" means here

Only the Linux artifact has been executed (full smoke suite in docs/TESTING.md).
Windows/macOS artifacts are **assembled with the identical, Linux-proven omni.ja
procedure** but have not been executed on their target OS — no Windows/macOS hardware
in the test matrix yet. VM capability on the dev host: qemu + KVM + virt-manager are
installed; a Windows VM image is the missing piece (owner to provide a licensed image).

## Update archives (for the deferred update service)

Upstream also ships `.mar` update archives per platform (`linux.mar`, `windows.mar`,
`macos.mar`, `linux-aarch64.mar`, `windows-arm64.mar`). They are the future backbone of
Shallette's own update channel (see ARCHITECTURE.md — deferred); a badge edition built
from a `.mar` would land as an update payload, not a full package.

## Android (GeckoView badge edition)

Source: official Firefox for Android (Fenix) 159.0 arm64 APK from
archive.mozilla.org (Zen has no Android build — this is Shallette's mobile line on
the same Gecko engine, with Fenix's UI).

Pipeline (proven end-to-end on the dev host):
1. Extract `assets/omni.ja`, run the standard string sweep (brand.ftl keys,
   `\bFirefox\b` / `\bZen\b` → Shallette in l10n; 300 files patched in 159.0).
2. Repack omni.ja (python zipfile).
3. Rebuild the APK preserving each entry's original compression method (resources.arsc
   stays STORED), drop `META-INF/` (old signature).
4. `zipalign -f 4`, sign with a project keystore (`~/shallette-android.keystore`,
   keytool RSA 2048), verify with `apksigner verify` — **PASS**.

Artifact: `shallette-0.0.1-android-arm64.apk` (137.7 MB, signed).

Known limits: the launcher label and icon still read as Firefox — they live in
`resources.arsc`, which needs an arsc-aware pass (apktool) planned separately. UI text
inside Gecko surfaces is Shallette-branded; Fenix chrome strings are not.

## VM testing

qemu + KVM + virt-manager are installed on the dev host. A boot probe of the local
`evrisselle-test.qcow2` (Tumbleweed jeOS) was performed headless via the QEMU monitor
(`screendump`): the image boots to jeOS Firstboot. Full in-VM Shallette tests need the
firstboot pass and a desktop snapshot — next step; a licensed Windows image would
unlock Windows-artifact tests.
