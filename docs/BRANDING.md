# Brand direction and attribution

Shallette needs a visual identity that is original, consistent, and easy to distinguish from any browser project it may build on. The final design is not yet approved; this document sets the direction and review checks for that work.

## Brand character

The intended character is **calm, polished, and self-assured**. Use graceful forms and restrained detail, with clear hierarchy and crisp interaction feedback. The interface should feel composed rather than decorative: motion, color, and ornament should help users understand what is happening.

These are design goals, not claims about an existing interface. Do not present mockups as screenshots of a working browser.

## Identity system

Create and document original Shallette assets for:

- wordmark and application icon;
- core and accessible color palettes;
- typography and icon treatment;
- browser chrome and interaction details;
- installer, website, and release artwork, if those are created.

Keep the source files for shipped assets and record each asset's creator, source, date, and license. Check that the selected name and mark are distinguishable from existing browser brands before public launch.

## Upstream names and marks

Use other product names only when needed to state a verified technical relationship or compatibility fact. Do not place upstream logos, icons, artwork, or names in Shallette's product name, domain, application icon, installer, or release branding without the relevant permission. Do not suggest that an upstream project sponsors, publishes, or endorses Shallette.

If Shallette incorporates Mozilla technology or Zen Browser code, verify the relationship and required notices against the exact source revision before making public claims. A factual relationship statement may be used where appropriate, for example:

> Shallette is an independent project and is not officially associated with Mozilla, Firefox, or Zen Browser.

Use that statement only if it accurately describes the project at the time of publication. It does not replace license notices or other required attribution. See [`LICENSING.md`](LICENSING.md).

## Publication checks

Before publishing brand material:

1. Confirm that the name, mark, and visual system are original or appropriately licensed.
2. Verify every upstream relationship and compatibility statement against the implementation.
3. Use screenshots from an actual build; remove personal data and private browsing information.
4. Check that installer and release artwork do not imply endorsement.
5. Preserve attribution required by licenses for incorporated code and assets.
